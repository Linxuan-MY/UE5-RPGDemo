# RPGDemo v1.0.0 Shipping 发布设计

## 目标

发布公开的 `v1.0.0` GitHub Release。Release 包含一个 Windows Shipping 构建，以 `MainMenuMap` 为启动地图，并包含 `SurvivalGameModeMap`。同时根据项目当前内容准确、简洁地更新仓库 README。

## 发布内容

构建只显式 Cook 以下地图：

- `/Game/Maps/MainMenuMap`
- `/Game/Maps/SurvivalGameModeMap`

`MainMenuMap` 继续作为游戏和编辑器的默认启动地图。玩家从主菜单开始游戏后进入 `SurvivalGameModeMap`，从游戏返回主菜单时重新加载 `MainMenuMap`。

发布源码提交包含当前主菜单、生存模式实现及其必要依赖：

- 主菜单、选项、帮助、暂停、胜利和失败 Widget；
- 主菜单与生存模式 GameMode 资产；
- 关卡查询、输入模式、加载界面、难度存档和生存波次相关 C++ 变更；
- 暂停输入资产，以及相关 Hero Blueprint 和输入映射变更；
- 生存模式使用的敌人波次数据与行为变更；
- `MainMenuMap`、`SurvivalGameModeMap` 和生存地图的 BuiltData；
- 通过 Git LFS 跟踪的 `Content/InfinityBladeIceLands/**`；
- 发布配置、README、设计规格和实施计划。

发布提交不包含当前 `FeatureDevMap` 修改及其外部 Actor 删除。这些文件作为用户的未提交工作保留在主工作区。

## 版本与打包配置

`Config/DefaultGame.ini` 设置 `ProjectVersion=1.0.0`，保留现有 Windows Shipping、Pak、IoStore、压缩和运行库前置依赖配置，并将原有 `CombatTestMap` Cook 条目替换为两个发布地图。

`Config/DefaultEngine.ini` 保持 `MainMenuMap` 为 `GameDefaultMap` 和 `EditorStartupMap`，并继续使用 `BP_RPGDemoGameInstance` 处理基于标签的关卡查询和加载界面。

Windows 发布物路径为：

```text
Releases/v1.0.0/RPGDemo-v1.0.0-Windows-Shipping.zip
```

发布结果同时提供该压缩包的 SHA-256 摘要。

## 构建隔离与源码一致性

只在 `main` 上暂存并提交发布范围内的文件。创建发布提交后，从该提交建立隔离 worktree 并执行 BuildCookRun，防止主工作区中未提交的 `FeatureDevMap` 状态进入构建。

最终的附注标签 `v1.0.0` 指向通过验证的发布提交。创建公开 GitHub Release 前，先将同一提交推送到 `origin/main`。

## 验证

编译、Cook、Stage、归档或上传任一环节失败时停止发布。验证项目包括：

- C++ 编译结果和 Unreal AutomationTool 退出状态；
- 两个显式地图均成功完成 Shipping Cook；
- Stage 目录包含 `RPGDemo.exe` 以及非空的 Pak、UCAS 和 UTOC 容器；
- Manifest 中同时存在 `MainMenuMap` 和 `SurvivalGameModeMap`；
- 从 `MainMenuMap` 启动打包程序的烟测；
- 直接加载 `SurvivalGameModeMap` 的打包程序烟测；
- ZIP 完整性检查和 SHA-256 生成；
- 远端标签和公开 GitHub Release 均指向发布提交；
- GitHub Release 中存在非空的 Windows Shipping ZIP。
