# RPGDemo v0.1.2 Shipping Release Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build `/Game/Maps/CombatTestMap` from committed `main` as a Windows Shipping package, tag the exact source state as `v0.1.2`, and publish the packaged game as a GitHub Release asset.

**Architecture:** Use an isolated `release/v0.1.2` worktree so uncommitted Survival/GameMode development in the primary checkout cannot enter the build or release commit. Keep `CombatTestMap` as both the packaged entry map and the sole explicit cook map, set the project version to `0.1.2`, then use Unreal Automation Tool to build, cook, stage, and archive the Windows Shipping target. Validate the staged executable and IoStore/Pak containers, validate and hash the ZIP, commit the release metadata, push the exact commit and annotated tag, and verify the published GitHub Release asset.

**Tech Stack:** Unreal Engine 5.4, Unreal Automation Tool, Windows Shipping target, Git LFS, Git, GitHub CLI, 7-Zip.

---

### Task 2: Build and validate the Windows Shipping package

**Files:**
- Generate (ignored): `Releases/v0.1.2/Windows/**`
- Generate (ignored): `Releases/v0.1.2/RPGDemo-v0.1.2-Windows-Shipping.zip`

- [ ] **Step 1: Build, cook, stage, and archive CombatTestMap**

Run:

```powershell
& 'E:\UE engine\UE_5.4\Engine\Build\BatchFiles\RunUAT.bat' BuildCookRun `
  -project='E:\UE_Projects\RPGDemo\.worktrees\release-v0.1.2\RPGDemo.uproject' `
  -noP4 -utf8output -platform=Win64 -clientconfig=Shipping `
  -build -cook -map=/Game/Maps/CombatTestMap `
  -stage -pak -iostore -compressed -prereqs `
  -archive -archivedirectory='E:\UE_Projects\RPGDemo\.worktrees\release-v0.1.2\Releases\v0.1.2\Windows'
```

Expected: `AutomationTool exiting with ExitCode=0 (Success)`.

- [ ] **Step 2: Verify the staged package**

Run:

```powershell
$releaseFiles = Get-ChildItem 'Releases\v0.1.2\Windows' -Recurse -File
$releaseFiles | Measure-Object -Property Length -Sum
$releaseFiles | Where-Object Name -eq 'RPGDemo.exe'
$releaseFiles | Where-Object Extension -in '.pak','.utoc','.ucas'
Select-String -Path 'Releases\v0.1.2\Windows\Manifest_UFSFiles_Win64.txt' -Pattern 'CombatTestMap'
```

Expected: the build is non-empty, `RPGDemo.exe` and `.pak`/`.utoc`/`.ucas` containers exist, and the UFS manifest contains cooked `CombatTestMap` files.

- [ ] **Step 3: Create and validate the release archive**

Run:

```powershell
& 'E:\7-Zip\7z.exe' a -tzip -mx=7 `
  'Releases\v0.1.2\RPGDemo-v0.1.2-Windows-Shipping.zip' `
  '.\Releases\v0.1.2\Windows\*'
& 'E:\7-Zip\7z.exe' t 'Releases\v0.1.2\RPGDemo-v0.1.2-Windows-Shipping.zip'
Get-FileHash 'Releases\v0.1.2\RPGDemo-v0.1.2-Windows-Shipping.zip' -Algorithm SHA256
```

Expected: both 7-Zip commands report `Everything is Ok`, and a SHA-256 hash is printed.

### Task 3: Commit, tag, push, and publish

**Files:**
- Commit: `Config/DefaultGame.ini`
- Commit: `docs/superpowers/plans/2026-07-30-v0.1.2-shipping-release.md`
- Publish: `Releases/v0.1.2/RPGDemo-v0.1.2-Windows-Shipping.zip`

- [ ] **Step 1: Stage and verify only the release metadata**

Run:

```powershell
git add Config/DefaultGame.ini docs/superpowers/plans/2026-07-30-v0.1.2-shipping-release.md
git diff --cached --check
git status --short
```

Expected: exactly the two release metadata files are staged; generated release output remains ignored.

- [ ] **Step 2: Commit the exact packaged source state**

Run:

```powershell
git commit -m "release: prepare v0.1.2 combat test build"
```

Expected: one commit is created on `release/v0.1.2`.

- [ ] **Step 3: Confirm the remote base, then push the commit and annotated tag**

Run:

```powershell
git fetch origin main --tags
git merge-base --is-ancestor origin/main HEAD
git push origin HEAD:main
git tag -a v0.1.2 -m "RPGDemo v0.1.2"
git push origin v0.1.2
```

Expected: the ancestry check exits zero, `origin/main` advances to the release commit, and `v0.1.2` is present on `origin`.

- [ ] **Step 4: Publish the GitHub Release**

Run:

```powershell
gh release create v0.1.2 `
  'Releases\v0.1.2\RPGDemo-v0.1.2-Windows-Shipping.zip' `
  --repo Linxuan-MY/UE5-RPGDemo `
  --title 'RPGDemo v0.1.2' `
  --generate-notes `
  --verify-tag
```

Expected: GitHub prints the new Release URL.

- [ ] **Step 5: Verify the remote tag and Release**

Run:

```powershell
git ls-remote --tags origin refs/tags/v0.1.2
gh release view v0.1.2 --repo Linxuan-MY/UE5-RPGDemo --json url,isDraft,isPrerelease,tagName,targetCommitish,assets
```

Expected: the tag exists, the Release is neither draft nor prerelease, and `RPGDemo-v0.1.2-Windows-Shipping.zip` is listed with a non-zero size.
